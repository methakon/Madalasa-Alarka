## Acceptance

> "Wrong iss/aud/sub/email claim denied"

| Claim family | Verified denials |
|---|---|
| `iss` | `https://accounts.google.com/` (trailing slash), `http://…`, wrong case, `https://evil.invalid`, leading-space value and empty value all rejected. Only the exact Google issuer (or its documented alias) is accepted, and the alias is canonicalised **after** signature verification. |
| `aud` | wrong audience, `null`, empty string, 1025-char value and an empty array all rejected; a multi-audience token additionally requires a valid `azp` present in the configured presenters. |
| `sub` | missing, empty, 256-char, numeric, and values containing NUL/newline/DEL/C1 control characters all rejected; opaque mixed-case and non-Latin subjects are preserved byte-exactly when valid. |
| `email` | admin layer requires a string `email` (≤254, single `@`, ASCII-printable, no quote/backslash/angle bracket) **and** `email_verified` strictly boolean `true`; `false`, missing, and the string `"true"` are each rejected. |
| Also enforced | algorithm confusion (`none`, `HS256`, `RS384`, `PS256`, lowercase `rs256`, empty, null) and forbidden headers (`crit`, `b64`, `jwk`, `jku`, `x5u`), unknown/empty/over-long/numeric/NUL `kid`, `typ` variants, `exp`/`iat`/`nbf` ordering and skew, and a 5-minute admin login freshness bound on `iat`. Admin nonce must be 16–128 chars of `[A-Za-z0-9_-]` and must match the server-issued value. |

A key-lookup failure or exception fails closed **before** the identity callback runs, so a
key-service outage cannot be mistaken for an authenticated admin.

  verified Google subject bound to a role server-side; this task does not grant a session or
  any child-data access.
- No live Google endpoint was contacted: JWKS is served from the local fixture, so real
  network fetching, caching and rotation behaviour is covered separately by `test_jwks_fetch`
  and remains NOT_RUN against Google itself.
