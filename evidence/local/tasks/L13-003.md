## Acceptance

> "Capability scan and permission checklist accurate"
> "Actual OS state only"

1. **Separation of Hardware Detection and Runtime Grants:**
   - Implemented `PermissionChecklistEvaluator` and `PermissionChecklistView` in `org.madalasa.alarka.ui.screens`.
   - Hardware sensor or chip presence (e.g. GPS hardware detected) is strictly isolated from OS runtime permission state (`isPermissionGranted`). Ungranted permissions are never presented as granted.
2. **Two-Step Location Permission Enforcement:**
   - On Android 10+ (API 29+), foreground location (`ACCESS_FINE_LOCATION` / `ACCESS_COARSE_LOCATION`) and background location (`ACCESS_BACKGROUND_LOCATION`) are modeled and evaluated as separate checklist gates.
3. **Notification Grant API Differences:**
   - On Android 13+ (API 33+), runtime grant `POST_NOTIFICATIONS` is required. On API < 33, evaluated against system `notificationsEnabled`.
4. **Covert Surveillance Prohibited:**
   - Camera and microphone sensors are audited as hardware items only. Runtime covert capture permissions are permanently denied (`isPermissionGranted = false`, status "Strictly Prohibited & Inactive"), satisfying Google Play Child Safety and India DPDP requirements.
