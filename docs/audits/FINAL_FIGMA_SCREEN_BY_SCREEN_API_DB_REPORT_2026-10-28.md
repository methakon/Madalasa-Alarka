These are **NOT backend handlers**. Existing 112 conceptual table cards plus 8 additional ERD11 cards = **120 proposed tables**, none of the 8 are executable migrations.

**Visual limitation:** per-screen Figma existence, editable structure and metadata checked; representative screenshots inspected for Theme C Home, administrator approval, new audit table and ERD11. This is NOT 187 separate pixel-by-pixel visual or accessibility approvals. Original 81 frames remain developer specs, 46 capability and 28 media frames are earlier design handoffs, 22 Theme C/story screens are selected samples, and 10 admin back-office screens are static prototypes. New 187-row audit is an editable inventory.

## Cross-screen implementation blockers confirmed

1. **P0 — No full runtime:** GitHub tree contains no built Android Gradle client modules, live C++ Drogon handlers or working Admin Web server; design is far ahead of implementation.
2. **P0 — Authorization/schema mismatch:** `0001_m1_identity.sql` grants are FK-bound to `guardian_memberships` in the same home/billing family, while blended-family requirement needs an independent external-parent exact-child authority. Current M1 RLS checks exact child, so do not weaken it or automatically add siblings; design reviewed [here](../data-model/FIGMA_SCREEN_GAP_PHYSICAL_SCHEMA_REVIEW_2026-10-28.md).
3. **P0 — External verification absent:** Google Sign-In is identity only; no supported third-party Google Family Link parent-role attestation was verified. Child-sharing grant activation must stay OFF pending trusted child-specific verification.
4. **P0 — Admin server missing:** verified Google-sub owner bootstrap, applicant profile/email challenge, owner-only Approve/Reject, staff role revocation, FAQ CMS and support replies are only proposed contracts and static Figma.
5. **P0 — Payment provider evidence absent:** founding first 1,008 *distinct paying families*, paid child seats, manual prepaid, 100-day extra concurrent viewer, +1 slot and 1800 pooled combined A/V seconds need actual verified Google Play one-time/SKU implementation and concurrency tests.
6. **P0 — Child privacy:** the Admin CHILD list must contain masked child ID/seat state only, never GPS, app behavior, recordings, messages or device telemetry; owner/admin roles cannot bypass. API schema corrected to `AdminChildSeatAlias`.
7. **P0 — Client-forged state risk fixed in contract only:** removed trust in client-supplied email_verified/contact_verified, price/verification, media approval state and asserted author/role. Server derives from OIDC, Play, device and owner RBAC.
8. **P0 — India legal/data retention:** six-hour free history is a visibility policy. Owner-suggested account-lifetime GPS storage is not a lawful retention approval, nor is app usage/remote media processing approved.
9. **P1 — Visual completeness:** only selected Theme C samples from the 81 generic handoff screens are complete styled concepts; existing 46 onboarding and 28 activity audit states need harmonization and Android/desktop accessibility testing. Deprecated Figma master `AMAR-POLA` cover text corrected to `MADALASA · ALARKA`.
10. **P1 — API to executable database:** 120 logical entities include 8 new candidates (parent sessions, permission changes, notification read receipts, commute plans/revisions, tracking policy revisions, service incidents and per-request media OS approvals). They have NOT been migrated, RLS-tested or performance benchmarked.
