# Madalasa–Alarka email designs

Eleven source templates, each with accessible 600px-wide HTML and plain-text alternative. **These are unrendered templates, not a sending system.** Renderer must HTML-escape every variable and validate URLs against an HTTPS allowlist; subject variables require CRLF sanitization. Never treat arbitrary support content as markup. Keep transport/provider credentials outside the repository. The sender is chosen from the manifest under server policy, never user input. See [design contract](../../docs/phases/M7-commercial-integrations/01-commercial-plans-and-costing/EMAIL_LIFECYCLE_AND_SUPPORT_TEMPLATES_2026-11-01.md). No tracking pixels, sensitive child geodata or externally loaded imagery. Worker-reported outbound test sends are not evidence these specific templates were delivered.
